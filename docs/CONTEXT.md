# HousamoEmbedTrans 领域词汇

本文件是跨模块讨论的统一词汇表，记录当前已确认的领域概念及其语义边界。

## Language

- 领域术语以中文为准；代码中的英文标识符只作为实现映射，不改变本词汇表的含义。
- `active` 表示未来任务和历史记录的路由指针，不表示生命周期、执行状态、完成标记或是否正在运行；指针可以没有目标，也可以指向一个目标。

## Glossary

**游戏层**：按运行边界划分时，位于目标游戏进程、直接承接游戏对象与显示行为的一侧；它同时包含该进程内的 Java 与 JNI/Native 部分。

**HET 层**：按运行边界划分时，位于 HET 应用服务进程、拥有翻译任务、提供商执行和持久状态的一侧。

**Java 层**：按实现边界划分时，所有 Java 组件的统称；它横跨游戏层与 HET 层，既包含游戏侧 MainHook，也包含 HET 应用服务。

**JNI/Native 层**：按实现边界划分时，经 JNI 连接的 C/C++ 运行时一侧；当前主要位于游戏层。

**剧情**：游戏中可被捕获、整理并翻译的一段叙事内容，是剧情上下文的可关联对象。

**剧情上下文**：通过有序引用关联一个或多个剧情、用于解释翻译和摘要所需背景的上下文单元；同一剧情可以被多个上下文引用。

**上下文分类**：通过有序引用组织一个或多个剧情上下文的更高层分类，用于共享摘要、路由和管理关系；同一上下文可以被多个分类引用。

**活跃剧情上下文**：指向一个剧情上下文的未来路由指针；它表示未来新任务和历史记录默认关联的上下文，不表示该上下文正在执行或已经完成。该指针可以独立存在；当活跃上下文分类指针同时存在时，分类必须引用此上下文。

**活跃上下文分类**：指向一个上下文分类的未来路由指针；它表示未来任务和历史记录的默认分类，不表示分类的生命周期。若活跃剧情上下文指针同时存在，该分类必须引用该上下文。

**翻译任务**：针对剧情或其他可翻译对象执行提供商翻译，并跟踪完整结果保存及游戏侧保存确认的任务。翻译任务的执行状态和结果保存确认是两个独立维度，不能用一个状态替代另一个维度。

**Quest 局部回写**：翻译任务向当前游戏进程中已捕获的剧情对象提供的 best-effort 显示更新；它不修改磁盘 Scene，也不具有终态结果的可靠投递和确认语义。

**Quest 完整回写**：游戏取得已有完整翻译的剧情时，将整份翻译应用到当前游戏进程内剧情对象的回写；它不消费流式 Quest patch。

**Quest 回写事件流**：同一剧情译文槽位中，按先进先出顺序排列的局部译文块与原文恢复块；消费方只按事件顺序写入，不在写回时比较请求优先级。

**原文恢复块**：翻译请求被替换时，为整份剧情重新提供全部原文、建立统一原文基线的一次 Quest 回写事件；Native 先移除尚未消费的旧请求事件，再用该块恢复已经写入的旧内容，最后才接纳新请求事件。未写入游戏对象的旧块没有可恢复内容。

**Quest 回写目标集**：一次剧情捕获留下的候选回写位置集合；它不拥有游戏对象，使用前必须重新验证。

**Quest 回写拒绝报告**：游戏 Native 在 QuestWriter 无法安全应用整个回写块时，通过独立的 best-effort 旁路向 HET 层报告的用户通知事件；它不表示翻译任务失败，不改变任务取消或终态投递状态，也不为 Quest patch 增加 ACK 或可靠重投语义。

**剧情译文槽位**：由剧情与目标语言共同标识的一份可显示译文位置；不同目标语言属于不同槽位，彼此不构成覆盖关系。

**Quest 权威请求**：同一剧情译文槽位当前获准继续产生 Quest 回写事件的翻译请求，以当前权威 `requestId` 直接标识，不另设请求代次；它约束生产者，不用于重排已经进入回写事件流的事件。

**Quest 权威请求替换**：同一剧情译文槽位的较新请求只有在被接纳、且旧请求同时进入翻译任务取消时，才取得事件生产权；Native 以该接纳结果建立显示队列边界，移除尚未消费的旧事件、恢复已经写入的旧内容，并让新请求事件从原文基线之后开始。边界后到达的旧事件不再进入队列；旧请求随后形成的完整合法结果进入等待处理。

**翻译任务取消**：普通 Translation Job 按 `requestId` 取消时，`queued` 或 `running` 以同一持久化线性化点进入终态 `canceled`，并固定 `delivery_state=not_required`；取消会移除所有可领取索引，禁止后续 provider retry/repair、自动写回和终态交付。取消赢得竞态后到达的完整合法结果沿既有 `rejected_api_results` 文件/通知流程保存，等待用户处理，不自动重试或交付。Summary Job 不在该取消入口范围内。

**已取消任务的后续操作**：取消后保留任务及其请求，用户可在任务页的最近任务中查看，并明确选择重新执行或永久删除。同一请求处于需要用户处理状态时，任务页不再额外生成一条运行中条目。重新执行复用保留的请求并使用当前翻译设置；必须等待旧执行和修复工作退出，不能因重新进入剧情或重复投递而自动撤销取消。

**永久删除翻译任务**：所有状态的任务详情均提供删除入口。排队或运行中的任务先取消并等待执行退出，再移除对应 requestId 的任务目录和调度索引；等待显示、失败、已完成和已取消任务也可删除。与终态投递共享租约屏障，正在应用结果时提示重试，删除后不再允许新投递租约。不删除 Scene、已保存译文或单独保存的等待处理结果。先将目录移出正式任务命名空间，再删除文件；中断后的删除目录不能被恢复成任务，下次启动继续清理。摘要恢复和失败条目也提供删除入口，仅在无执行占用且状态仍可删除时清理任务，保留已保存摘要。

**等待处理结果**：已经失去自动应用资格、但仍完整合法并被保留供用户查看或删除的结果；它不包含未完成的局部流，也不表示关联翻译任务处于等待状态。

**摘要任务**：针对剧情上下文或上下文分类生成、确认并写回摘要的任务。成功写回目标后任务从长期任务集合中删除，不保留长期 `completed` 摘要任务历史。

**等待本地保存**：完整合法翻译结果已保留在任务中，但尚未提交到 HET Scene。本地保存失败只重试本地提交，不再请求 Provider；Scene 缺失、删除、管理等待或译文冲突时保留结果及原因，不自动覆盖或复活对象。

**Scene 保存回退**：优先写入 HET；只有确认 HET 对应 Scene 文件及原子备份均不存在时，才允许用已有完整结果走游戏终态写入和 ACK。HET 的删除意图、管理门禁、冲突、损坏或 I/O 错误不触发回退。游戏未连接显示“等待写入游戏”；游戏写入失败后确认原始 Scene 也不存在，通过匹配当前投递租约的缺失回报显示“两端均缺少剧情”。不删除结果、不自动重跑模型、不从结果重建原始 Scene。游戏 ACK 表示游戏已保存，不伪造 local_scene_saved；之后 HET Scene 到位仍可尝试补存。

**新翻译任务的 Scene 同步**：游戏 Native 先提交原始 Scene，再发送翻译请求。HET 成功接纳新任务后请求现有完整同步；同步期间的新请求合并为后续一次同步，未连接时由后续连接同步补齐。运行期同步与 API 领取、模型调用互不等待；仅启动阶段继续遵守首次同步、恢复决定、API 开放的顺序。同步仍遵守删除意图、冲突规则和 Scene 写入门禁；完成后唤醒保留结果的本地保存，不重新请求翻译。此触发不覆盖只解析而不提交翻译任务的场景。

该触发由“捕获与同步”中的“新翻译任务自动同步剧情”控制（`UserSettings.SceneSync.AutoSyncOnNewTranslation`，默认开启，旧配置缺失时补为开启）。服务在触发时读取已保存配置；关闭只阻止后续新任务触发，不取消已排定同步，不关闭连接同步、手动同步或结果本地保存恢复。

**等待游戏同步**：译文、Scene Summary 和语言元数据已提交到 HET Scene；未连接游戏时不投递，连接且 Scene Sync 门禁放行后才投递结果。旧称“等待显示”不再用于描述此阶段。

**游戏同步完成**：成功结果已在 HET 保存，并获得游戏侧结果保存 ACK；不表示当前剧情画面已刷新。Quest Patch 的画面应用是独立通道，没有显示 ACK。失败通知 ACK 不属于成功同步。已有 completed 任务使用保留结果补齐 HET Scene，保留有效游戏 ACK，不重新调用 API。

游戏层回退保存获得 ACK 的任务也计入完成，但详情明确注明仅游戏已保存、HET 原始 Scene 缺失；上述 HET 已保存的描述只适用于正常本地优先路径。

**当前应用**：负责承载任务、剧情管理、设置和用户操作的宿主应用；它协调任务状态与游戏、翻译服务之间的边界。

**游戏内存储**：由游戏侧持久化或读取的 Scene/翻译副本及其保存确认数据；当前应用通过明确边界与其交换数据，不能把应用内任务状态假定为游戏内存储本身。

**补充说明**：为理解剧情或执行翻译/摘要而附加的背景、来源或人工提供的信息；它不是任务执行状态，也不等同于摘要正文。

**人工摘要**：由用户直接编写并作为摘要来源保存的摘要内容，具有明确的人工来源和更新时间。

**阶段摘要**：对当前阶段或当前批次材料生成的摘要，用于在更完整的内容可用前提供阶段性上下文；它可以被后续摘要替换或提升。

**完整摘要**：在目标范围内材料充分后形成的最终完整上下文摘要；它表示内容覆盖程度，不表示相关任务仍然存在或正在运行。

## Avoid

- 不要把“游戏层/HET 层”这条运行边界与“Java 层/JNI/Native 层”这条实现边界混为同义词；同时涉及两条轴时使用“游戏 Java”“HET Java”或“游戏 Native”等限定语。
- 不要把 `active` 当作生命周期状态、执行状态、完成标记或“正在使用”的 UI 徽标。
- 不要把等待显示、已显示与翻译执行状态合并成单一枚举。
- 不要把摘要任务成功后的短期通知误当成长期 completed 任务，也不要把摘要写回误称为修改游戏内存储。
- 不要把 Quest 回写目标集称为“指针池”；它不分配对象、不延长对象生命周期，也不持续监听对象存活。
- 不要用 Quest patch 的最后到达顺序判断权威请求。
- 不要把被替换的旧翻译任务、未完成局部流和等待处理结果混称为“前一个进入等待处理”。
- 不要为了恢复旧请求而先应用尚未显示的旧事件；Native 在替换边界直接移除未消费事件，原文恢复块只负责把当前游戏对象建立为确定的原文基线。
- 不要用独立 generation 重复表达剧情译文槽位的当前权威请求；`patchVersion` 和连接代次也不承担跨请求排序。
- 不要让 HET 根据“已经发送”推断游戏内“已经显示”；Quest 回写事件流的入队边界和原文恢复位置由掌握实际显示状态的 Native 决定。
- 不要把 Quest 回写拒绝报告送入 Translation Job 的失败终态链；前者只是游戏显示失败通知，后者表示翻译执行已经失败。
- 在未经用户授权下，不允许修改任意跨`游戏`与`HET`进程的数据结构。
