# HET 功能说明

本文面向日常使用者，介绍 Housamo Embed Trans（HET）的主要功能、设置用途和任务处理方式。内容按 2026-09-21 的实现整理，具体按钮名称以应用显示为准。

安装方式和使用前须知见 [README](../README.md#快速开始)。代码结构与实现细节分别见 [游戏层开发文档](game-layer-development.md) 和 [HET 层开发文档](het-layer-development.md)。

## 1. 游戏内剧情翻译

HET 从游戏中读取剧情正文、说话人和选项，交给配置的模型翻译，再把译文写回游戏显示。日常阅读无需截图识别，也无需逐句复制到外部翻译工具。

剧情会整理成可保存的 Scene，包含正文、选项及可解析的分支关系。翻译可以使用角色词典、游戏术语和前序剧情摘要，帮助模型保持称呼与情节的一致性。遇到已有目标语言官方译文的剧情，按现有规则跳过自动翻译。

已保存译文可以在重新进入剧情时复用。游戏更新、剧情数据变化或同步冲突时，仍需根据具体状态处理，不能保证任意版本的数据都可直接互换。

### 捕获与剧情处理

通知中的 **暂停新捕获／恢复捕获** 控制游戏新剧情的捕获，不会取消已接纳的翻译任务；停止已有任务应到任务页操作。

| 选项 | 用途与区别 |
| --- | --- |
| 覆盖已有剧情文件 | 控制捕获同名剧情时是否允许替换已有本地剧情文件；不是“立即重新翻译”按钮 |
| 剧情处理线程 | 控制 Scene 处理线程数量，范围为 1–4；与服务请求并发数不同 |

### 首页入口

首页的 **任务、管理、剧情同步** 分别进入任务处理、已保存数据管理及剧情同步页面。**项目仓库**打开项目页面，供查看说明和发布内容。更新与资源检查见第 7 节，等待翻译排序见第 5 节。

## 2. 翻译接口与基本设置

根据自己的模型服务配置接口地址、凭据和模型。当前支持 OpenAI 兼容接口与 Anthropic Messages 接口；不能只凭模型名称选择协议，应以服务方实际提供的接口为准。

| 设置 | 用途 |
| --- | --- |
| 协议、服务地址与模型 | 决定请求发送到哪里，以及使用哪种消息格式和模型 |
| 目标语言 | 指定译文语言 |
| 提示词 | 调整翻译要求、表达习惯等；编辑时需保留程序要求的输出格式 |
| 输出长度上限 | 限制单次响应允许生成的 token 数，不是输入容量，也不是保证会输出这么多内容 |
| 模型上下文上限 | 用于判断剧情、提示词和历史等材料是否能放入请求，应按所选模型能力配置 |
| API 并发数 | 控制同时执行的 API 工作数量，翻译与摘要共同使用额度 |
| 网络重试次数 | 控制网络或可重试传输问题的再次尝试 |
| 结果修复次数 | 控制输出未通过校验后，向模型请求修复的次数 |

修改设置不能改变已经发送到服务方的请求。重跑任务会使用当前翻译设置，但应先等待旧执行结束。

### 接口与提示词操作

- **查询／选择模型**：使用服务地址和凭据查询可用模型列表，再选择模型；不会因此发起翻译。服务不支持查询时仍可手动填写模型名。
- **自定义目标语言**：除预置语言外，填写需要的语言名称或代码。
- **保存设置**：确认当前设置分类的修改。离开有未保存修改的页面时，可选择继续编辑或放弃修改。
- **翻译／摘要提示词**：在提示词编辑页分别编辑两类提示词。保存用于保留编辑结果；放弃修改用于退出当前草稿；恢复默认用于恢复相应内置提示词。修改时仍需保留程序需要的输出约定。

## 3. 流式输出与游戏回写

| 模式 | 行为 | 阅读体验 |
| --- | --- | --- |
| 流式 | 接收模型陆续返回的内容，校验可用的译文块并尝试回写 | 有机会在整段翻译结束前看到部分译文 |
| 非流式 | 等待服务方返回完整响应，再处理内容 | 等待期间可能没有正文输出 |

流式输出不等于模型一定会“思考一块、翻译一块”。首块何时出现，取决于模型思考、输出顺序和服务方实现。游戏也需要继续运行相应的显示逻辑，才能消费回写内容。

后台翻译由 HET 服务执行。游戏暂停、切到后台或被系统冻结时，模型请求与游戏画面刷新的进度可能不同；回到游戏后仍需等待游戏处理回写。Android 的后台限制也可能影响 HET 服务运行。

调试选项中的“不发送思考参数”表示请求中省略相关字段；它不等于要求模型停止思考。思考强度是否有效取决于所选服务和模型。

### 流式修复设置

| 选项 | 用途与区别 |
| --- | --- |
| 流式修复梯度次数 | 控制流式修复的梯度尝试次数，范围为 2–8；与网络失败后的重试次数不同 |
| 修复时带入完整场景 | 在适用的流式修复请求中带入完整剧情背景，会增加输入量 |

## 4. 剧情上下文与摘要

管理页中的三个层级分别是：

| 对象 | 用途 |
| --- | --- |
| 剧情（Scene） | 一段捕获的剧情及其译文 |
| 剧情上下文（Context） | 按顺序关联多段剧情，用于提供连续的历史背景 |
| 上下文分类（Group） | 组织多个上下文，承接更大范围的关系与摘要 |

活跃对象用于指定后续任务的关联方向，不表示该对象正在执行任务。可以利用摘要、补充说明和管理关系调整提供给后续翻译的背景。

长历史可以通过摘要压缩，减少后续请求需要携带的完整内容。自动压缩等行为受设置控制；摘要本身也需要 API 调用，可能产生额外耗时和用量。

同一上下文内，前面的剧情尚未产生摘要时，可在“翻译与修复”中选择：

| 选项 | 行为 | 取舍 |
| --- | --- | --- |
| 等待 | 等待前序摘要就绪后继续 | 背景更连贯，但后续任务可能等待 |
| 不等待 | 不等尚未就绪的摘要，使用当前可用历史继续 | 开始更快，但可能缺少前序背景 |
| 发送所有未产生总结的完整原文 | 将相关未完成摘要剧情的完整原文作为背景 | 保留更多背景，但输入量更大，可能触及上下文上限 |

并发数与摘要等待策略共同影响实际执行顺序。即使使用非流式响应，也可以并发执行独立任务；开启流式不会自动消除摘要等待。

### 新建与活跃对象

**新建上下文／新建分类**用于创建组织关系。Scene 来自捕获与同步，不通过这个入口手工创建原文。**设为活跃／取消活跃**调整后续任务的关联方向；**清除所有活跃上下文设置**同时清除活跃 Context 和 Group，不会自动选择替代对象，也不会删除原对象。

### 上下文与分类编辑

支持修改显示名称、添加不同语言的手动描述、管理手动摘要、添加／移除成员及调整成员顺序。Context 还可编辑所属 Group；Group 管理其有序 Context 成员。保存前的编辑只是草稿。

此编辑页的**恢复默认**会恢复本次打开时的初始草稿，放弃当前未保存的修改，不会清空全部上下文，也不会重新导入 APK 预设。

### 摘要压缩设置

| 选项 | 用途 |
| --- | --- |
| 上下文超限时自动压缩 | 允许通过摘要处理超出上下文预算的历史；相关摘要请求会消耗 API 用量 |
| 手动摘要后继续自动摘要 | 决定手动摘要之后是否继续自动摘要，配合自动压缩设置使用 |
| 启动时检查上下文摘要 | 在启动恢复决策前检查需要复核的摘要 |
| 摘要保留最近比例／最近剧情数 | 调整压缩时对近期剧情的保留策略；不是日志保留范围 |
| 剧情上下文摘要重试／上下文分类摘要重试 | 分别配置 Context 和 Group 的摘要重试次数 |

### 手动闭包：决定何时生成最终摘要

适合一段剧情还在持续收集、希望自行决定“到这里算一轮结束”的情况。它控制最终摘要的生成时点，不是暂停翻译。首次开启需要先将相应 Context 或 Group 设为活跃。

| 按钮 | 行为 |
| --- | --- |
| 开启手动闭包 | 开始手动控制这一轮的结束时点；开启期间暂停该对象相应的自动最终摘要生成，切换活跃对象不会自动结束这一轮 |
| 结束并生成摘要 | 使用已保存内容结束本轮并请求摘要；未保存的编辑草稿不包含在内 |
| 重试摘要／重试结束并生成摘要 | 处理本轮失败或尚未成功入队的摘要；已保存内容变化时需要按提示确认使用最新事实 |
| 重新开启闭包 | 开始新的一轮，不等于重试旧轮次，也不会自动取消旧摘要任务或更改活跃对象 |

Context 最终摘要基于其已保存的剧情事实；Group 摘要基于已保存的成员 Context 最终摘要。若 Group 提示缺少 Context Final 摘要，应先处理对应 Context；有活动摘要任务或没有可用事实时，界面也会说明为何不能结束本轮。生成摘要仍需调用 API，需要等待任务完成。

## 5. 任务页与常见状态

任务页用于查看翻译和摘要任务、失败原因及可执行操作。查找任务时可结合搜索、分组和最近任务记录，不能只看未完成任务数量。

| 状态或阶段 | 含义 | 如何处理 |
| --- | --- | --- |
| 等待翻译 / 排队 | 已有任务，尚未进入模型执行 | 查看是否需要排序、恢复选择、历史摘要或可用并发额度 |
| 翻译中 | 正在请求、接收或处理模型内容 | 查看进度和日志；必要时停止翻译 |
| 等待保存到 HET | 完整结果已保留，但还没成功写入 HET 剧情 | 处理缺失、冲突等原因；系统重试本地保存，无需因此重新翻译 |
| 等待游戏同步 | HET 已保存，尚未获得游戏侧保存确认 | 保持游戏连接，等待同步门禁放行 |
| 游戏同步完成 | 游戏已确认保存结果 | 不代表当前画面一定已经刷新 |
| 失败 / 需要处理 | 请求、校验或本地数据存在问题 | 阅读详情中的具体原因，再选择修复、重跑或删除 |
| 已取消 | 任务已停止自动执行与交付 | 可查看保留资料，显式重跑或删除 |

正常情况下，完整译文先保存到 HET，再同步到游戏。若确认 HET 缺少对应原始 Scene，可按现有回退路径尝试游戏保存；两端均缺失时会保留结果并报出原因。冲突、损坏和删除状态不会一律当作“文件缺失”绕过。

### 停止、重跑与删除

- **停止翻译**：取消当前任务，阻止后续自动重试和交付。已产生的服务方用量可能仍会计费；取消后迟到的完整合法结果会保留到等待处理，未完成内容不作为完整结果保存。
- **重新执行**：使用保留请求和当前设置重新运行，需要等待旧执行及修复退出。仅重新进入同名剧情不等于主动撤销取消。
- **删除任务**：所有任务状态提供删除入口。运行中的任务先取消并等待退出；正在应用结果时可能需要稍后重试。删除任务不会同时删除剧情、已保存译文或单独保留的等待处理结果。
- **启动恢复**：翻译和摘要分别按各自设置恢复，选择规则见下方“恢复与执行顺序”。

摘要成功写入目标后，不保留长期“已完成摘要任务”条目；应到相应上下文或分类中查看摘要内容。

### 恢复与执行顺序

| 选项 | 用途 |
| --- | --- |
| 自动恢复翻译任务／自动恢复摘要任务 | 分别决定启动时是否自动恢复两类旧任务，两项可以独立设置 |
| 恢复顺序 | 自动恢复时可按创建时间或开始时间，选择旧到新或新到旧；尚未开始的任务按现有创建时间回退规则处理 |

首页的 **等待翻译排序** 在有待安排的 Scene 时进入排序界面，支持选定顺序并分批提交；任务页的 **设置恢复顺序／提交顺序** 用于安排实际待恢复任务。手动翻译等待队列未选任务继续等待。

**应用摘要恢复决定** 会恢复选中的旧摘要任务，丢弃未选中的旧摘要任务；不要将它与翻译队列分批提交混淆。

### 查找任务与故障处理

| 操作 | 用途与注意点 |
| --- | --- |
| 搜索、分类和排序 | 按对象查找，或按最近更新、对象名称、需要处理优先、完成状态等方式查看任务；列表显示排序不等于改变 API 执行队列 |
| 修复后重试 | 修正映射、上下文或长度等原因后，让被阻塞任务重新尝试 |
| 启用自动压缩 | 对适用的上下文超限任务启用自动压缩并重新排队，也会更新对应设置 |
| 同步或修复 Scene／移入损坏数据 | 针对源数据问题处理；不是普通网络错误的重试入口 |
| 重新运行摘要 | 将保留的失败摘要任务重新排队，可能再次产生 API 用量 |

### 保留的 API 结果

失去回写资格的结果可能保留为等待处理记录。**查看原始 payload**用于检查保留的 API 内容；**删除记录**永久移除该归档，不等于删除已保存的 Scene，也不会自动重新翻译。这类记录不会自动清理。

## 6. 剧情、词典与数据管理

### 内置预设

APK 内置 16 份剧情和“梦之岛灯笼祭”上下文，供查看剧情、译文、摘要与关联关系。HET 服务首次初始化时自动导入，在首次游戏同步前完成；不需要手动选择文件，也不会仅因导入而创建翻译任务。

已有同一对象时跳过，不覆盖用户数据，不更改活跃上下文。导入中断后从原事务恢复，完成后不再重复导入；覆盖安装不会自动恢复用户已删除的预设。清除应用数据或卸载后重新安装会重新进入初始化流程。

### 查找与批量选择

独立列表按对象类型查找；剧情结构树按已保存的关联展示，支持全部展开和全部收起。搜索用于缩小当前查找范围。

进入**批量管理**后，可全选、反选、清空选择。切换分类时保留所选对象；执行前应核对全部选择，而不只看当前页。支持导出所选对象和批量移入等待处理。语言记录、损坏任务只能用于相应的移入操作，不能混入普通导出；主角 MC 受保护，不能按普通对象批量移入等待处理。

### 剧情详情与编辑

- **翻译语言**：切换要查看的已保存译文，与原文及分支内容对照。
- **角色／术语详情**：查看当前剧情使用的资料。词典记录与只属于当前剧情的临时记录不同，临时记录只读展示。
- **编辑剧情**：管理摘要等可编辑资料；不会改写捕获的剧情名称和原文。
- **新增手动摘要**：填写人工背景补充，与模型生成的摘要记录区分。
- **语言操作／将某语言移入等待处理**：只处理所选语言记录；与移动整个 Scene 不同。
- **移入等待处理**：隐藏整个对象并保留可处理的快照，具体影响先看确认窗口；不是删除翻译任务。

### 编辑全部 Scene

这个入口同时提供“上下文成员与顺序”和“新任务历史”两部分：

1. 为各个 Context 添加或移除 Scene，并用上移、下移调整各自的剧情顺序。移除成员关系不等于删除 Scene 文件。
2. 在 API 部分，为需要新建翻译任务的 Scene 选择历史 Context／Group，并选择是否发送 API。修改成员关系本身不代表要求重新翻译。
3. 点击**确认并提交**前核对关系修改、新任务及受影响旧任务的数量。已有任务可能被识别为重复，不能保证每次点击都会再建一个任务。

提交前，修改仍是编辑草稿。若关系修改影响尚未发送的手动摘要任务，界面会要求确认取消这些任务；已经运行的摘要任务不会因此直接取消，过时结果按现有规则保留处理。并发修改导致事实变化时，需要重新核对后提交。

### 角色词典与游戏术语

角色词典提供姓名、别名及背景，游戏术语帮助统一专有名词。资料按正文命中和相关性参与翻译，不表示每次发送全部词典。

可以新增或编辑词典条目、译名及相关字段；角色编辑还包括别名、学校、公会、来源世界、关系、说话风格等。数组字段通过添加和删除项维护，完成后按页面提供的应用／保存操作确认。

**编辑 MC**用于主角记录。**恢复默认词典**会移除对应用户词典覆盖并恢复内置内容，不能把它当成只撤销当前输入。**角色词典更新冲突**用于核对内置更新与用户编辑的差异：无冲突内容自动合并，冲突字段由用户选择，未解决时保留用户值。

### 角色匹配与资料筛选

这些设置决定哪些词典资料进入翻译背景，不会直接修改词典内容。

| 选项 | 主要影响 |
| --- | --- |
| 高相关性／中相关性门槛 | 根据发言、立绘出现和正文点名等信息判断角色相关性 |
| 集中出现门槛 | 判断角色是否集中出现在当前剧情中 |
| 次要角色点名门槛 | 非主要角色在正文中被提及到何种程度时带入完整资料 |
| 仅名称点名门槛 | 判断何时只带入名称和译名 |
| 关联提升门槛 | 根据与主要角色的词典关联，判断是否提升为次要角色 |
| 次要角色术语门槛 | 决定次要角色共同关联的公会、学校、来源世界等术语是否进入背景 |
| 详细匹配规则 | 展开查看角色命中、分组和术语上下文的计算说明 |

### 导入数据

普通管理导入按以下步骤进行：

1. 选择一个或多个 HET JSON 文件，等待读取和类型识别完成；不需要的文件可从本次选择中移除。
2. 确认文件，进入预检。遇到同一对象时，选择**覆盖现有对象、创建副本或跳过**；可设置全局默认，也可逐项选择。
3. 核对受影响的活动翻译任务，按界面提示决定保留还是确认取消。
4. 点击**生成导入预览**，检查每个源文件的计划操作，再点击**应用导入**。

预览后数据发生变化时，应重新预检。若已经提交但服务尚未确认结果，保留并重试原导入会话，不要误以为尚未提交而反复创建导入。

角色／术语页也提供直接导入词典的入口，遇到同名项可保留同名并导入其他，或确认替换现有条目；当前编辑尚未保存时先保存，再导入。

### 导出数据

选择对象后进入**导出预览**。可以对单个文件点击**下载 JSON**，也可以点击**选择目标目录**导出整组文件；取消导出不修改源对象。

- Scene 各自输出独立 JSON；Context 文件放在 `contexts/`，Group 文件放在 `groups/`。
- 选中的角色汇集为 `chardict.json`，选中的术语汇集为 `gameterms.json`，并非每个词典条目各占一个文件。
- 导出不自动打包等待处理对象和无关对象；选择关联对象时应自行核对所需集合。
- 导出的 Scene 顶层末尾依次为 `protect`、`seq_to_order`。仅调整导出副本的阅读顺序，不修改字段内容、内部保存文件或 API 请求顺序。
- 目录导出逐文件写入，可能部分成功。根据结果中的成功／失败数量检查目标目录，不要将部分成功当成全部完成。

### 剧情同步与冲突处理

HET 与游戏各自保存剧情副本。连接同步、手动同步或新任务触发同步时，可能需要处理两侧差异。不要用删除任务代替冲突处理。

**新翻译任务自动同步剧情** 控制新任务是否触发同步。关闭后仍可进行连接同步与手动同步，已有翻译结果不会因此被删除。

**同步剧情**用于主动交换游戏和 HET 的剧情数据。冲突策略可选：

| 策略／操作 | 用途 |
| --- | --- |
| 每次询问 | 遇到需要选择的冲突时等待用户处理 |
| 以游戏内容为准 | 按游戏侧内容处理冲突 |
| 以本地翻译为准 | 按 HET 侧内容处理冲突 |
| 展开文本对比 | 在冲突详情中核对两侧差异 |
| 使用游戏版本／使用 HET 版本 | 为当前冲突选择保留的一侧 |

选择前应确认哪侧包含需要保留的内容。操作若仍需等待同步门禁放行后处理，应等提交结果，不能只凭已点击按钮就认定同步完成。

### 等待处理对象

“移入等待处理”通常会隐藏对象并保存快照，供之后恢复或永久删除。它与“等待翻译”的任务队列不同。

| 按钮 | 用途 |
| --- | --- |
| 预览影响／详情 | 查看对象、原因及关联影响，再决定如何处理 |
| 恢复 | 将可恢复的对象重新置为可用；仅允许删除的记录不能恢复 |
| 永久删除 | 删除保留的数据，无法通过该记录恢复；删除前核对对象与语言范围 |
| 刷新 | 重新获取当前列表和处理状态 |

移动 Scene 并不表示游戏副本已立即清除；确认窗口会说明游戏侧清理与永久删除的关系。移动某语言、整个 Scene、Context 或 Group 的影响范围不同，应按预览确认。

## 7. 应用更新、资源版本与 OBB

### HET 应用更新

首页的 **HET 更新卡片** 展示应用更新状态，并提供版本发布页入口。HET 应用更新与运行时适配资源更新分别处理。

### 运行时资源

应用启动时会读取项目仓库的运行时资源，确认其版本匹配已安装游戏，再比较本地与远端规范化 JSON 的 SHA-256；内容不同就自动更新，同版本的资源修正也会生效，缩进或字段顺序变化不触发更新。点击首页资源版本也可主动检查。资源更新后，需要重启游戏以重新加载配置。

运行时资源包含游戏接口定位信息，与剧情译文、OBB 不是同一种数据。资源版本不匹配时，不应只通过改版本字符串来绕过检查。

### OBB 配置

在设置页进入“OBB 配置”，先保证游戏中的 HET 模块已启用并与 HET 连接，再点击“检查并补齐 OBB”。

该功能按游戏版本寻找同版本 Release，例如游戏 `5.19.0` 对应 `v5.19.0`。只下载缺失文件，不覆盖已有同名文件，也不校验文件内容；已有文件损坏时，不能靠“文件存在”判断资源正常。

下载窗口显示当前文件进度和大小；检查及保存阶段显示处理中。服务器未提供文件大小时无法显示准确百分比。处理中关闭窗口或按返回键需二次确认，点击窗口外不会关闭。确认退出会取消检查或下载，但已经开始的游戏端保存仍会完成。补齐后完全退出并重新启动游戏。

## 8. 日志、诊断与问题反馈

### 日志导出与反馈

HET 与游戏侧模块日志分别按日期保存在各自的内部目录。导出时请保持游戏连接，ZIP 会按 `het/`、`game/` 收录两端日志，默认范围为包括当天在内的近期 14 天。游戏未连接时只导出 HET 日志，并显示未包含游戏日志的提示。该范围是导出范围，不等于只保存 14 天日志。

调试选项可以开启 API 请求与响应正文打印，便于核对实际发送和返回的内容。正文日志体积可能较大，反馈前应检查其中的剧情、提示词和其他不希望公开的信息。

反馈时尽量提供：

1. HET 与游戏版本、使用的模块环境。
2. Scene 名称、任务请求 ID 和问题发生时间。
3. 实际操作、任务状态和错误文字。
4. 对应日期的日志；若是游戏闪退，还需要游戏或系统崩溃日志，HET 日志不能覆盖所有游戏进程事件。

### 诊断开关与样式核对

| 入口 | 用途 |
| --- | --- |
| PageRec 剧情导出 | 捕获链切换为完整 Scene 导出，逐项优先简中、繁中，缺失时使用日文；文件保存到游戏私有 `page_rec/`，不参与同步、翻译或回写。保留游戏连接，切换需重启游戏 |
| 仅解析诊断 | 只解析，不提交翻译请求；开启后没有新翻译任务可能正是此设置的效果 |
| 保存失败响应诊断 | 留存失败响应供分析，与打印所有 API 请求／响应正文的开关不同 |
| 样式核对 | 用内存样例查看真实任务页和管理页的视觉状态，不写入正式数据，也不发送翻译请求 |

本文描述当前代码提供的功能，不代表每种设备、模型或后台环境均已验证。新增 OBB 弹窗进度和退出确认目前完成静态核对，实际交互仍需设备验证。
